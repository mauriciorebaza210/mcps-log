- **Quote Tool bugs found during the CP5 preview check (2026-11-09; all pre-existing, live on main; fix on their own branch off main, not here):**
  1. ✅ Fixed on this branch (8acc00e): "Open in Quote Tool" always showed an empty form. `qLoadQuote` called `apiLocalGet('/api/quotes/get')` without the session token (`apiLocalGet` never adds one), so every reopen was a 401 since bc9afa2 (2026-08-25). Ships with this branch unless split out to main sooner.
  2. Saving an edit to a **pool startup** quote is refused with "Select at least one startup service." `qSaveEdit` (js/features/quotes.js) doesn't send `startup_chemical` / `startup_programming` / `startup_pool_school`, and `mergedInput` in api/_repo/quote-update.js doesn't read the stored selections, so the startup price is $0 and pricing.js rejects it. The stored flags live in the Quotes export (`startup_chemical_work`, …) and can be derived from the proposal items' SKUs (START-CHEM, START-PROGRAM, POOL-SCHOOL). Also `toQuoteToolState` (api/quotes/index.js, opGet) doesn't return them, so a reopened startup quote shows the wrong chips.
  3. The 400 above shows as "Network error saving changes." (misleading; it's a validation error).
  4. The Quote Tool's "Save Changes" (`qSaveEdit`) returns silently when `_qS._calc.pricing_ready` is false, so a click can do nothing with no message. Seen on the preview: no `/api/quotes/update` request after a reopen + save at 15:16.
